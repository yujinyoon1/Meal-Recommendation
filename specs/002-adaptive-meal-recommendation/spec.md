## 1. 비즈니스 모델 요약 (Context)

001 단계에서 "보유 재료 × 개인 영양 프로필 × 1인 가구 조건"의 1회성 추천 MVP를 완성했다. 본 002 단계(중기)는 그 추천을 **사용자 행동을 학습하여 시간이 지날수록 정교해지는 적응형(Adaptive) 추천**으로 끌어올리고, 식재료를 **유통기한 단위로 능동 관리**하며, 사용자의 **건강 변화를 추적·시각화**하는 데 목적이 있다.

| 영역 | 핵심 내용 |
|---|---|
| **해결 문제** | (1) 추천이 매번 초기화되어 개인화가 누적되지 않음 (2) 식재료 폐기가 여전히 발생 (3) 건강 변화 추이를 사용자가 체감하지 못함 |
| **핵심 가치** | 누적 학습 기반 개인화 만족도 향상, 음식물 폐기 절감, 체계적·시각적 건강관리 |
| **차별점** | 단발 추천 → "피드백·재사용·소비패턴을 누적 반영하는 학습 루프" + "유통기한 임박도를 추천 가중치로 직접 환산" |
| **범위 우선순위** | (P1) AI 추천 고도화·피드백 학습 → (P1) 식재료 소비·유통기한 관리 → (P2) 건강 분석 리포트·시각화 → (P2) 자동 장보기 고도화. 외부 상품/헬스케어 API 연동은 **선택(가능 시)** 으로 분리 |

### 1.1 In Scope (이번 단계)
- 피드백·재사용·소비 패턴을 누적 반영하는 개인화 추천 가중치 학습
- 식재료 유통기한 임박 알림 및 임박 재료 우선 소비 추천
- 만족도 평가·추천 수정 이력 수집 및 추천 반영
- 체중·건강 변화 추적과 영양/건강 리포트 시각화(캘린더·그래프)
- 자동 장보기 리스트 정확도 향상(부족분 자동 정리·구매 추천)

### 1.2 Out of Scope (이번 단계 제외)
- 외부 식품 상품/마트 가격 실시간 연동, 헬스케어 기관/기기·헬스 앱 데이터 연동 → **선택적·후속**(FR-040 참고, 가능 시에만)
- 외부 푸시·이메일 알림 채널(본 단계는 인앱 통지만)
- 결제/구독, B2B 솔루션, 모바일 네이티브 앱
- 영양사 실시간 상담, 자동 위험 알림(의료 행위)

## Clarifications

### Session 2026-06-05

- Q: 식재료 '유통기한 임박'의 판정 기준 → A: **식품군별 차등** 임계(예: 채소 2일 / 육류 3일 / 유제품 5일). 식품군 분류와 군별 임박 임계 기준을 데이터로 관리.
- Q: 개인화 추천 '학습'의 구현 범위 → A: **통계 가중치·규칙 기반** 개인화. 본 단계에서 별도 ML 학습 파이프라인은 도입하지 않음.
- Q: 유통기한 임박/만료 알림의 전달 채널 → A: **인앱(대시보드) 통지만**. 외부 푸시·이메일은 본 단계 범위 외(후속 선택).
- Q: 건강 분석 리포트의 건강/체중 데이터 수집 방식 → A: **사용자 수동 기록만**. 외부 기기·헬스케어 앱 연동은 본 단계 범위 외(FR-040 선택 후속).

## 2. User Scenarios & Testing *(필수)*

### 2.1 Primary User Story

> 3개월째 서비스를 사용 중인 1인 가구 사용자 A는 그동안 "매운맛 선호·해산물 저평가·아침 간편식 선호"라는 피드백을 누적해 왔다. A가 냉장고 재료를 입력하자, 시스템은 **유통기한이 2일 남은 두부를 우선 소비하는 식단**을, A의 과거 만족도 패턴(매운맛↑, 해산물↓)을 반영하여 상위에 추천한다. A는 추천을 한 끼만 살짝 수정(밥→현미밥)해 저장하고, 그 수정 이력도 학습된다. 주말에 A는 **건강 리포트**를 열어 최근 4주 체중 추이와 주간 평균 영양 균형 그래프, "단백질 섭취가 권장 대비 15% 부족" 같은 요약을 확인하고, 부족분을 채우는 **자동 장보기 리스트**를 받는다.

### 2.2 Acceptance Scenarios

| # | Given (전제) | When (행동) | Then (기대 결과) |
|---|---|---|---|
| **AS-1** | 피드백 이력이 N건 이상 누적된 사용자 | 추천을 요청 | 과거 만족도가 높았던 카테고리/식재료의 가중치가 상향되어 추천 순위에 반영됨 |
| **AS-2** | 유통기한이 임박(임계 이내)한 보유 재료 존재 | 식단을 생성 | 임박 재료를 우선 소비하는 식단이 상위에 노출되고, 임박 사유가 표시됨 |
| **AS-3** | 보유 재료 중 임박/만료 항목 존재 | 대시보드 진입 또는 알림 시점 도달 | "임박 식재료 N건" 알림과 소비 우선순위 목록이 표시됨 |
| **AS-4** | 추천 결과를 받은 사용자 | 추천을 부분 수정(재료 교체/메뉴 제외) 후 저장 | 수정 이력이 저장되고, 이후 추천에 해당 선호가 반영됨 |
| **AS-5** | 과거에 저장한 식단이 있는 사용자 | "다시 추천/재사용" 선택 | 저장 식단을 기준으로 재사용 추천이 생성되고 재사용 횟수가 기록됨 |
| **AS-6** | 체중을 주기적으로 기록한 사용자 | 건강 리포트 화면 진입 | 기간별 체중 추이, 주간 평균 영양 균형, 부족/과잉 영양소 요약이 그래프로 표시됨 |
| **AS-7** | 추천 식단이 일일 권장 영양 대비 부족 | 장보기 리스트 생성 | 부족 영양소를 채우는 식재료가 우선순위·수량과 함께 자동 정리됨 |
| **AS-8** | 동일 사용자가 일정 기간 사용 | 추천 정확도/만족도 집계 시점 | 만족도 지표가 산출되어 리포트와 내부 품질 지표에 반영됨 |

### 2.3 Edge Cases

- **EC-1**: 피드백 이력이 부족(콜드스타트)한 신규/저활동 사용자 → 기본 프로필 기반 추천으로 폴백하고 학습 미적용을 명시
- **EC-2**: 상충하는 피드백(같은 식재료에 고평가/저평가 혼재) → 최신성·빈도 가중으로 종합하되, 임계 이하 신뢰도면 중립 처리
- **EC-3**: 유통기한 미입력 재료 → 임박 추천에서 제외하되 일반 추천에는 포함, 입력 보완 유도
- **EC-4**: 임박 재료만으로 균형 식단이 불가능 → 임박 우선 + 부족분 장보기 제안을 병행
- **EC-5**: 체중/건강 기록이 1~2건뿐 → 추이 그래프 대신 "데이터 누적 안내"를 표시
- **EC-6**: 학습된 선호가 알레르기/기피와 충돌 → **결정적 안전 검증(알레르기 차단)이 학습 가중치보다 항상 우선**
- **EC-7**: 추천 다양성 부족(같은 식단 반복 학습 고착) → 다양성 보장 로직으로 주기적 변형 노출
- **EC-8**: 외부 상품/헬스케어 API 미연동·실패 → 내부 데이터만으로 정상 동작(선택 기능 graceful degrade)

## 3. Functional Requirements *(필수)*

### 3.1 AI 추천 고도화 · 피드백 학습 (P1)
- **FR-001 (개인화 가중치 학습)**: 시스템은 사용자의 누적 피드백(만족도)·식단 재사용·추천 수정 이력을 반영하여 식재료/메뉴 카테고리별 선호 가중치를 산출하고 추천 순위에 적용해야 한다. 학습은 **통계 가중치·규칙 기반**으로 수행하며(본 단계에서 별도 ML 학습 파이프라인은 도입하지 않음), 최신성·빈도 가중을 적용한다.
- **FR-002 (피드백 수집 확장)**: 사용자는 추천에 대해 만족도(척도)와 코멘트를 남길 수 있고, 추천을 부분 수정(재료 교체·메뉴 제외·대체)한 이력이 수집되어야 한다.
- **FR-003 (학습 반영 가시성)**: 추천 결과에는 "왜 이 추천인지"(예: 과거 선호 반영, 임박 재료 우선)에 대한 간단한 근거가 사용자에게 표시되어야 한다.
- **FR-004 (콜드스타트 처리)**: 학습 데이터가 임계 미만인 사용자는 기본 프로필 기반 추천으로 동작하며, 학습 미적용 상태가 구분되어야 한다.
- **FR-005 (안전 검증 우선)**: 학습된 선호 가중치는 알레르기/기피 식재료의 결정적 차단 규칙을 절대 무력화하지 못한다(001 FR-015 유지·강화).
- **FR-006 (다양성 보장)**: 동일/유사 식단이 단기간 반복 추천되지 않도록 다양성 로직이 적용되어야 한다.
- **FR-007 (추천 정확도 측정)**: 추천 채택률·만족도 기반의 정확도 지표가 산출·집계되어야 한다(목표 75% 이상).

### 3.2 식재료 소비 · 유통기한 관리 (P1)
- **FR-010 (유통기한 관리)**: 사용자는 보유 식재료에 유통기한(또는 구매일+소비기한)을 입력·수정할 수 있어야 하며, 각 재료는 임박 임계 산정을 위한 **식품군**으로 분류되어야 한다.
- **FR-011 (임박 알림)**: 시스템은 유통기한이 임박한 재료를 감지하여 **인앱(대시보드)** 으로 통지해야 한다. 임박 판정 임계는 **식품군별로 차등** 적용한다(예: 채소 2일 / 육류 3일 / 유제품 5일). 외부 푸시·이메일 채널은 본 단계 범위 외이다.
- **FR-012 (소비 우선순위 추천)**: 식단 생성 시 임박 재료를 우선 소비하도록 추천 가중치에 반영하고, 임박 사유를 결과에 표시해야 한다.
- **FR-013 (소비 패턴 기록)**: 추천 채택/식단 저장에 따른 식재료 소비가 기록되어 소비 패턴 데이터로 축적되어야 한다.
- **FR-014 (만료 처리)**: 유통기한 경과 재료는 추천에서 제외되고 사용자에게 경고/정리 안내가 제공되어야 한다.

### 3.3 식단 저장 · 재사용 (P1)
- **FR-020 (식단 저장)**: 사용자는 추천받은 식단을 저장하고 이름/메모를 붙일 수 있어야 한다.
- **FR-021 (식단 재사용)**: 사용자는 저장 식단을 기반으로 재추천을 받을 수 있고, 재사용 횟수가 기록되어 학습에 반영되어야 한다.

### 3.4 건강 분석 리포트 · 시각화 (P2)
- **FR-030 (건강 기록)**: 사용자는 체중 및 주요 건강 지표를 **직접 수동으로** 주기적으로 기록할 수 있어야 한다. 본 단계에서 외부 기기·헬스케어 앱 연동은 범위 외이며, 핵심 리포트 경로는 수동 입력 데이터만으로 완결되어야 한다.
- **FR-031 (추이 시각화)**: 기간별 체중·건강 변화 추이를 그래프로 제공해야 한다.
- **FR-032 (영양 리포트)**: 주/월 단위 평균 영양 균형, 부족/과잉 영양소 요약을 시각적으로 제공해야 한다(영양 그래프 신뢰도 향상).
- **FR-033 (캘린더 뷰)**: 식단 이력을 캘린더 기반으로 조회할 수 있어야 한다.
- **FR-034 (면책 고지)**: 모든 건강 리포트에는 "의학적 진단/처방이 아님" 면책이 포함되어야 한다(001 FR-017 유지).

### 3.5 자동 장보기 리스트 고도화 (P2)
- **FR-035 (부족분 자동 정리)**: 추천/저장 식단과 보유 재고를 비교하여 부족 식재료를 수량과 함께 자동 정리해야 한다.
- **FR-036 (구매 추천 우선순위)**: 장보기 항목은 영양 부족도·임박 대체 필요성 등을 기준으로 우선순위가 매겨져야 한다.

### 3.6 데이터 · 거버넌스 · 연계
- **FR-037 (데이터 관계 강화)**: 사용자/식단/추천/피드백/소비 데이터가 관계형으로 연결되어 학습·리포트의 근거로 사용되어야 한다.
- **FR-038 (민감정보 보호)**: 건강·체중 등 민감 데이터는 001의 보호 체계(앱 레벨 암호화·동의 기반)를 준수해야 한다.
- **FR-039 (입력 검증)**: 사용자 입력(식재료·유통기한·체중)은 검증되어 비정상 값이 학습/리포트 품질을 훼손하지 않아야 한다.
- **FR-040 (선택적 외부 연계)**: 공공 영양 데이터, 식품 상품 정보, 헬스케어 기관 데이터 연동은 **가능한 경우 확장**하되, 미연동 시에도 핵심 기능이 정상 동작해야 한다.

## 4. Success Criteria *(필수)*

측정 가능하고 구현 비종속적인 결과 지표:

- **SC-001 (추천 정확도)**: 중기 단계 종료 시 추천 채택/만족도 기반 정확도가 **75% 이상**을 달성한다.
- **SC-002 (추천 만족도)**: 추천 식단 만족도 평균이 **80% 이상**을 유지한다.
- **SC-003 (음식물 폐기 절감)**: 임박 우선 소비 기능 사용 사용자의 식재료 폐기율이 도입 전 대비 **20% 이상 감소**한다.
- **SC-004 (식단 생성 시간)**: 사용자가 추천 식단을 확정하기까지 걸리는 시간이 기존 대비 **50% 단축**된다.
- **SC-005 (사용자 유지율)**: 중기 단계 사용자 4주 유지율이 **70% 이상**이다.
- **SC-006 (학습 체감)**: 일정 사용 후 사용자의 **80% 이상**이 "추천이 내 취향에 맞게 개선되었다"고 평가한다.
- **SC-007 (임박 알림 적시성)**: 임박 식재료는 만료 전 알림이 제공되며, 임박 항목의 우선 소비 추천 노출률이 **90% 이상**이다.
- **SC-008 (리포트 가용성)**: 충분한 기록이 있는 사용자는 체중 추이·영양 균형 리포트를 즉시 확인할 수 있다.

## 5. Key Entities *(데이터 관련)*

- **사용자 선호 모델(UserPreferenceWeights)**: 사용자별 식재료/카테고리 선호 가중치. 피드백·재사용·수정 이력에서 파생. (사용자 1:1)
- **피드백(Feedback) [확장]**: 만족도 척도, 코멘트, 그리고 추천 수정 이력(교체/제외/대체)을 포함. (사용자·추천 N:1)
- **식재료 보유 항목(InventoryItem) [확장]**: 유통기한/소비기한, **식품군 분류**, 임박 상태, 소비 여부를 포함. (사용자 1:N)
- **식품군 임박 임계(FoodGroupExpiryThreshold)**: 식품군별 임박 판정 일수 기준(예: 채소 2일 / 육류 3일 / 유제품 5일). 설정값으로 관리.
- **소비 패턴 기록(ConsumptionRecord)**: 식재료가 언제 어떤 추천을 통해 소비되었는지의 이력. (사용자 1:N)
- **저장 식단(SavedMealPlan)**: 사용자가 저장한 식단과 재사용 횟수·메모. (사용자 1:N)
- **건강 기록(HealthLog)**: 시점별 체중·건강 지표(민감 데이터, 암호화 대상). (사용자 1:N)
- **건강/영양 리포트(HealthReport)**: 기간별로 집계된 영양 균형·추이 요약(파생/캐시 가능).
- **추천 요청·결과(Recommendation) [연계]**: 학습 가중치·임박도 반영 근거와 정확도 측정의 기준.

---

## 6. Assumptions (가정)

- 001 단계의 회원/프로필/식재료 입력/AI 추천/영양 검증/기본 피드백/장보기 기능은 **운영 중이며 본 단계의 기반**이다.
- "학습"은 **통계 가중치·규칙 기반** 개인화를 의미한다(본 단계에서 별도 ML 학습 파이프라인 미도입) — 명세는 결과 행동을 규정한다. *(Clarified 2026-06-05)*
- 추천 응답 성능 목표(001의 P95 ≤ 30s)는 본 단계에서도 유지된다.
- 알림은 **인앱(대시보드) 통지만** 제공한다(외부 푸시·이메일은 범위 외). *(Clarified 2026-06-05)*
- 건강/체중 데이터는 **사용자 수동 입력**으로 수집하며, 외부 기기·헬스 앱 연동은 범위 외이다. *(Clarified 2026-06-05)*
- 외부 상품/헬스케어 API는 가용성이 보장되지 않으므로 핵심 경로는 내부 데이터만으로 완결되어야 한다.
- 유통기한 "임박" 임계는 **식품군별 차등 기준**(설정값)으로 관리한다(예: 채소 2일 / 육류 3일 / 유제품 5일). *(Clarified 2026-06-05)*

## 7. 위험 · 제약 · 거버넌스 (Risks & Governance)

| 위험 | 영향 | 완화 방안 | 책임 주체 |
|---|---|---|---|
| **AI 추천 오류·영양 불균형** | 사용자 신뢰도 저하 | 결정적 영양/알레르기 검증을 학습보다 우선, 추천 로직 테스트 강화, (선택) 영양사 검증 | AI 개발팀, 협력 영양사 |
| **입력 데이터 품질 저하** | 학습/리포트 신뢰도 하락 | 입력 검증(FR-039), 이상치 필터, 콜드스타트 폴백(FR-004) | 데이터 관리팀 |
| **AI API·서버 비용 증가** | 운영 부담 | 추천 캐시·재사용 활용, 비용 최적화, 기능 우선순위 기반 개발 | 운영 관리자 |
| **초기 사용자 이탈** | 사용자 감소 | 개인화 체감 강화(FR-003), 리포트로 가치 가시화 | 서비스 운영팀 |
| **민감 건강정보 유출** | 법적·신뢰 리스크 | 앱 레벨 암호화·동의 기반 수집(FR-038), 최소 수집 원칙 | 데이터 관리팀 |

**거버넌스**: AI 개발팀(추천 알고리즘·모델 개선), 데이터 관리팀(데이터 품질·검증), 서비스 운영팀(피드백 분석·개선), 협력 영양사(식단 검증·건강 기준 자문).
