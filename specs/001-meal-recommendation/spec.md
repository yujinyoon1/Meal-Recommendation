## 1. 비즈니스 모델 요약 (Context)

본 서비스는 **1인 가구의 식재료 낭비와 불규칙한 식습관**이라는 사회적 문제를 데이터 기반으로 해결하기 위한 AI 식단 추천 플랫폼이다.

| 영역 | 핵심 내용 |
|---|---|
| **타깃 사용자** | 1인 가구 (학생, 사회초년생, 1인 자취/독립 생활자) |
| **핵심 가치** | (1) 개인 맞춤형 건강관리 (2) 보유 식재료 기반 음식물 낭비 최소화 (3) 식단 고민에 소요되는 시간·비용 절감 |
| **차별점** | 단순 레시피 검색이 아닌 "보유 재료 × 개인 영양 프로필 × 1인 가구 조건(소용량/간편/설거지 최소화)"의 정밀 결합 |
| **수익 모델** | 구독형(프리미엄 리포트), 커머스 연계 수수료, B2B 솔루션, 맞춤형 광고 |
| **MVP 우선순위** | 사용자 프로필 + 보유 식재료 입력 + AI 식단 추천 + 영양 검증 + 피드백 + 장보기 리스트 (커머스/B2B/구독 결제는 후속 단계) |

## 2. User Scenarios & Testing *(필수)*

### 2.1 Primary User Story

> 자취 중인 사회초년생 A는 퇴근 후 냉장고를 열고 남은 식재료(예: 계란 2개, 양파 1개, 두부 반 모, 김치)를 확인한다. A는 웹사이트에 보유 식재료를 텍스트로 입력하고, 자신이 사전에 등록한 "체중 감량 + 견과류 알레르기 + 매운 음식 선호" 프로필이 자동 결합되어, **30초 이내에 1인분 탄수화물·단백질·지방 균형 식단**과 함께 영양 분석 그래프, 부족한 영양소를 채울 수 있는 **장보기 리스트**까지 받는다. 식사 후 만족도(별점 + 한 줄 코멘트)를 남기면, 다음 추천은 A의 취향에 더 가까워진다.

### 2.2 Acceptance Scenarios

| # | Given (전제) | When (행동) | Then (기대 결과) |
|---|---|---|---|
| **AS-1** | 신규 방문자 | 회원가입 후 온보딩 화면에서 기본/건강/식습관 데이터를 입력 | 개인 영양 프로필이 저장되고 메인 대시보드로 이동 |
| **AS-2** | 프로필이 완성된 사용자 | "냉장고 입력" 화면에 보유 식재료를 텍스트로 입력 후 "추천받기" 클릭 | 1인분 기준 맞춤 레시피 1~3건과 영양 분석 그래프가 표시됨 |
| **AS-3** | 알레르기(예: 견과류)가 등록된 사용자 | 견과류가 포함된 레시피 후보가 AI에 의해 생성됨 | 시스템이 해당 레시피를 자동 차단/대체하여 알레르기 식재료가 결과에 노출되지 않음 |
| **AS-4** | 추천 결과를 받은 사용자 | 별점(1~5) 및 코멘트로 피드백 제출 | 피드백이 저장되고, 다음 추천에서 유사 카테고리 가중치가 조정됨 |
| **AS-5** | 추천 식단이 사용자의 일일 권장 영양소 대비 부족할 경우 | 영양 검증 단계에서 부족분 감지 | 부족 영양소를 채울 수 있는 식재료가 "장보기 리스트"로 제안됨 |
| **AS-6** | 보유 식재료의 유통기한이 임박한 항목이 존재 | 식단 생성 시 유통기한 데이터 참조 | 임박 식재료 우선 활용 레시피가 상위에 노출됨 |
| **AS-7** | 동일 사용자가 일정 기간 사용 후 | 추천 이력 화면 진입 | 과거 추천 식단/피드백/만족도 추이를 시간순으로 확인 가능 |

### 2.3 Edge Cases

- **EC-1**: 입력 식재료가 0개 또는 식단 구성이 불가능할 만큼 적을 때 → "필수 재료가 부족합니다" 안내 + 최소 장보기 제안
- **EC-2**: 알레르기 등록 항목과 입력 보유 재료가 충돌할 때 → 해당 재료를 제외하고 진행하며 경고 메시지 표시
- **EC-3**: 유통기한 지난 재료 입력 → 제외 + 경고
- **EC-4**: AI 응답 실패/타임아웃 → 재시도 안내 및 캐시된 유사 추천 폴백
- **EC-5**: 추천 식단이 일일 권장 영양 균형을 만족시키기 어려운 경우 → "오늘은 외부 식품 보충 추천" 메시지와 함께 부족 영양소 표시
- **EC-6**: 사용자 프로필 미완성 상태에서 추천 시도 → 부족한 항목 입력 요청
- **EC-7**: 입력 식재료 표기가 모호한 경우(예: "고기") → AI/시스템이 정규화 후보를 제시하고 사용자 확인 요청
- **EC-8**: 동일 식단이 단기간 내 반복 추천될 때 → 다양성 보장 로직으로 변형 메뉴 우선 노출

## 3. Functional Requirements *(필수)*

### 3.1 회원 및 프로필
- **FR-001 (회원가입/인증)**: 사용자는 이메일 기반 회원가입과 로그인을 수행할 수 있어야 한다.
- **FR-002 (기본 프로필)**: 사용자는 나이, 성별, 키, 체중을 입력하고 BMI는 자동 산출되어 저장되어야 한다.
- **FR-003 (건강 프로필)**: 사용자는 알레르기, 질병 이력(당뇨/고혈압 등 선택형), 건강 목표(감량/유지/증량)를 등록·수정할 수 있어야 한다.
- **FR-004 (식습관 프로필)**: 사용자는 평균 식사 시간/횟수, 외식·배달 빈도, 기피 식재료, 선호 음식 카테고리를 등록할 수 있어야 한다.
- **FR-005 (프로필 변경 이력)**: 시스템은 프로필 변경 이력을 보존하여 시점별 추천 컨텍스트를 재현 가능해야 한다.

### 3.2 식재료 인벤토리
- **FR-006 (재료 입력)**: 사용자는 보유 식재료를 텍스트로 입력할 수 있어야 한다. (예: "계란 2개, 양파 1개, 두부 반 모")
- **FR-007 (재료 정규화)**: 시스템은 자유 텍스트를 표준 식품 항목으로 매핑/정규화해야 한다.
- **FR-008 (수량/유통기한 옵션)**: 사용자는 선택적으로 수량 및 유통기한을 함께 입력할 수 있어야 한다.
- **FR-009 (인벤토리 유지)**: 입력된 식재료는 사용/소모 표시 또는 만료 시까지 인벤토리에 유지되어야 한다.

### 3.3 AI 식단 추천
- **FR-010 (1인분 맞춤 추천)**: 시스템은 사용자 프로필 + 인벤토리 데이터를 결합한 정교한 프롬프트로 1인분 기준 식단·레시피를 생성해야 한다.
- **FR-011 (1인 가구 특화 조건)**: 추천은 "간편 조리", "설거지 최소화", "소용량 조리", "조리 시간 30분 이내(기본값)" 조건을 반영해야 한다.
- **FR-012 (탄단지 균형)**: 추천 식단은 사용자의 건강 목표에 따른 탄수화물·단백질·지방 비율 가이드를 따라야 한다.
- **FR-013 (유통기한 우선 활용)**: 인벤토리 내 유통기한 임박 재료가 우선 사용되도록 가중치를 부여해야 한다.
- **FR-014 (대체 재료 제안)**: 누락된 필수 재료가 있을 경우 대체 가능한 재료를 함께 제시해야 한다.

### 3.4 안전 검증
- **FR-015 (알레르기/기피 차단)**: 시스템은 AI 생성 결과를 사용자의 알레르기/기피 항목 리스트와 대조하여 해당 항목이 포함된 결과를 차단·재생성해야 한다.
- **FR-016 (영양 검증)**: 시스템은 공공 영양 데이터베이스를 활용해 추천 식단의 칼로리·주요 영양소(탄/단/지/식이섬유/나트륨)를 산출하고 일일 권장량 대비 비율을 표시해야 한다.
- **FR-017 (의학적 면책 고지)**: 모든 추천 결과에 "의학적 진단/처방이 아님"을 명시해야 한다.

### 3.5 피드백 및 학습
- **FR-018 (만족도 수집)**: 추천 식단별로 별점(1~5)과 짧은 코멘트를 받을 수 있어야 한다.
- **FR-019 (선호도 강화)**: 수집된 피드백은 차후 추천 시 선호/비선호 가중치로 반영되어야 한다.
- **FR-020 (이력 조회)**: 사용자는 과거 추천 식단, 피드백, 영양 추이를 시간 순으로 조회할 수 있어야 한다.

### 3.6 장보기
- **FR-021 (부족분 도출)**: 영양 검증 결과 부족한 영양소를 채울 식재료를 시스템이 산출해야 한다.
- **FR-022 (장보기 리스트)**: 도출된 부족 재료는 장보기 리스트 형태로 출력되며 카테고리(채소/과일/육류/유제품 등)별로 정리되어야 한다.

### 3.7 개인정보 보호 및 동의
- **FR-023 (민감정보 암호화)**: 건강·식습관 등 민감 정보는 저장 시 암호화되어야 한다.
- **FR-024 (이용 동의)**: 회원가입 시 개인정보 처리, 건강정보 이용, 마케팅 수신에 대해 분리 동의를 받아야 한다.
- **FR-025 (열람·삭제·이전)**: 사용자는 본인 데이터를 열람/삭제/내보내기(JSON 등) 할 수 있어야 한다.
- **FR-026 (감사 로그)**: 민감정보 접근 이력은 감사 로그로 남겨야 한다.

### 3.8 운영 요구
- **FR-027 (가용성)**: 핵심 추천 기능은 영업 시간 기준 월 99% 이상의 가용성을 유지해야 한다.
- **FR-028 (응답 시간)**: 사용자 입력 후 첫 추천 결과 표시까지 95퍼센타일 30초 이내여야 한다.
- **FR-029 (외부 의존성 격리)**: AI/공공 데이터 등 외부 의존성 장애 시 사용자에게 명확한 상태 안내와 재시도 옵션을 제공해야 한다.

## 4. Key Entities *(데이터 모델 개요)*

> 본 섹션은 비즈니스 데이터 개념을 정의한다. 물리적 스키마/저장 방식은 plan 단계에서 결정한다.

| Entity | 설명 | 핵심 속성(요약) |
|---|---|---|
| **User** | 서비스 가입자 | 식별자, 이메일, 가입일, 동의 상태 |
| **BasicProfile** | 기본 신체정보 | 나이, 성별, 키, 체중, BMI(파생) |
| **HealthProfile** | 건강 정보 | 알레르기 목록, 질병 이력, 건강 목표(감량/유지/증량) |
| **DietPreference** | 식습관·기호 | 식사 횟수/시간, 외식·배달 빈도, 기피·선호 카테고리 |
| **IngredientItem** | 보유 식재료 단위 | 정규화 명, 수량, 유통기한, 등록일 |
| **InventorySnapshot** | 추천 시점의 인벤토리 묶음 | 사용자, 시점, 항목 리스트 |
| **RecommendationRequest** | 추천 요청 | 사용자, 시점, 입력 인벤토리, 사용된 프로필 스냅샷 |
| **Recipe** | AI가 생성한 레시피 | 명, 재료, 조리 단계, 예상 조리 시간 |
| **MealPlan** | 추천 결과 묶음 | 1식 또는 1일 단위 레시피 집합 |
| **NutritionAnalysis** | 식단의 영양 분석 | 칼로리, 탄/단/지, 식이섬유, 나트륨, 권장량 대비 비율 |
| **Feedback** | 사용자 만족도 | 별점, 코멘트, 추천 ID |
| **ShoppingList** | 부족분 기반 장보기 리스트 | 카테고리, 항목, 수량 |
| **ConsentRecord** | 동의 이력 | 항목, 동의 시점, 철회 시점 |
| **AuditLog** | 민감정보 접근 기록 | 행위자, 행위, 대상, 시점 |

## 5. Success Criteria *(측정 가능한 성과 지표)*

### 5.1 사용자 경험
- **SC-1**: 신규 사용자의 **초기 프로필 입력 완료율 ≥ 70%** (가입 후 24시간 내)
- **SC-2**: 보유 식재료 입력부터 첫 추천 결과 표시까지 **95퍼센타일 30초 이내**
- **SC-3**: 추천 식단 평균 만족도 **4.0/5.0 이상** (월 평균)
- **SC-4**: 가입 후 1개월 시점 **재방문율 ≥ 60%**

### 5.2 안전성·신뢰성
- **SC-5**: 추천 결과 중 알레르기/기피 항목이 노출된 비율 **0.1% 이하**
- **SC-6**: 영양 검증 단계에서 일일 권장 칼로리 대비 ±15% 이내로 정합되는 추천 비율 **≥ 90%**
- **SC-7**: 민감정보 관련 보안 사고 **0건** (연간 기준)

### 5.3 비즈니스/사회적 임팩트
- **SC-8**: 4주 이상 이용 사용자 그룹의 **식재료 폐기율 자가 보고 30% 이상 감소**
- **SC-9**: 4주 이상 이용 사용자의 **외식·배달 빈도 자가 보고 20% 이상 감소**
- **SC-10**: 사용자 NPS(추천 의향) **+30 이상**

### 5.4 운영
- **SC-11**: 핵심 추천 기능 **월 가용성 ≥ 99%**
- **SC-12**: AI 응답 실패 시 폴백 동작이 명시적으로 표시되는 비율 **100%**

## 6. Assumptions

- **A-1**: 1차 채널은 **반응형 웹**이며, 모바일 네이티브 앱은 후속 단계로 분리된다.
- **A-2**: 1차 UI 언어는 **한국어**이며 사용자는 한국 거주 1인 가구를 우선 대상으로 한다.
- **A-3**: 식품 영양 정보는 **식품의약품안전처/농림축산식품부 공공 데이터**를 권위 있는 출처로 사용한다.
- **A-4**: AI 추천은 **외부 LLM 서비스**를 활용하며 본 명세는 특정 모델/벤더에 종속되지 않는다.
- **A-5**: 식재료 입력은 **텍스트 입력**을 기본으로 한다(이미지/바코드 인식은 비범위).
- **A-6**: 본 서비스는 **의료 행위가 아닌 정보 제공**이며, 의학적 진단/처방을 대체하지 않는다.
- **A-7**: 인증은 이메일 + 소셜 로그인을 표준 옵션으로 가정한다(상세 옵션은 plan 단계에서 확정).
