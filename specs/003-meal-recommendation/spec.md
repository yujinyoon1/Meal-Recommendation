## 1. 정보화 비전 · 목표 (Context)

AI 기반 데이터 분석을 통해 1인 가구의 건강 상태와 식습관을 실시간으로 관리하고, 식재료 낭비를 최소화하는 **개인 맞춤형 스마트 식단 추천 플랫폼**을 구축한다.

| 영역 | 핵심 내용 |
|---|---|
| **해결 문제** | (1) 보유 식재료를 활용하지 못해 음식물 쓰레기 발생 (2) 기존 식단 서비스의 개인 건강 상태 반영 부족 (3) 추천이 누적 학습되지 않아 개인화가 정체 (4) 건강 변화 추이 체감 어려움 |
| **핵심 가치** | 개인화 만족도 향상, 비용·시간 절감, 음식물 폐기 절감, 체계적·시각적 건강관리 |
| **차별점** | "건강 상태·알러지 기반 정밀 추천" + "피드백·재사용·소비패턴을 누적 반영하는 학습 루프" + "유통기한 임박도를 추천 가중치로 직접 환산" + "시각화 기반 UI" |

### 1.1 정보화 목표 (정량)
- 추천 식단 만족도 평균 **80% 이상** 달성
- 사용자 식재료 폐기율 **20% 이상 감소**
- 식단 생성(확정) 시간 기존 대비 **50% 단축**
- AI 학습 기반 추천 정확도 **75% 이상**, 4주 사용자 유지율 **70% 이상**

### 1.2 In Scope (플랫폼 전체)
- 회원/프로필/알러지·기피 관리, 보유 식재료 입력·관리
- 건강 상태·영양 프로필 기반 AI 식단 추천 및 결정적 영양/알레르기 검증
- 피드백·재사용·소비 패턴을 누적 반영하는 개인화 추천 가중치 학습
- 식재료 유통기한 임박(식품군별 차등) 알림 및 임박 재료 우선 소비 추천
- 체중·건강 변화 추적과 영양/건강 리포트 시각화(캘린더·그래프)
- 부족분 자동 정리·우선순위 기반 자동 장보기 리스트
- 공공 영양 데이터 기반 칼로리·탄단지 계산

### 1.3 Out of Scope (제외 / 선택적 후속)
- 외부 식품 상품·마트 가격 실시간 연동, 헬스케어 기관/기기·헬스 앱 데이터 연동 → **선택적·후속**(FR-040, 가능 시에만)
- 외부 푸시·이메일 알림 채널(본 플랫폼은 인앱 통지만)
- 결제/구독, B2B 솔루션, 모바일 네이티브 앱
- 영양사 실시간 상담, 자동 위험 알림 등 의료 행위

## 2. User Scenarios & Testing *(필수)*

### 2.1 Primary User Story

> 1인 가구 사용자 A는 회원가입 후 건강 정보(키·체중·목표)와 알러지(갑각류)를 등록한다. 냉장고 속 재료를 입력하면, 시스템은 알러지를 결정적으로 배제하고 건강 프로필에 맞는 식단을 칼로리·탄단지와 함께 추천한다. 사용을 거듭하며 A의 "매운맛 선호·해산물 저평가" 피드백이 누적되어 추천이 점점 취향에 가까워지고, **유통기한 2일 남은 두부를 우선 소비하는 식단**이 상위에 노출된다. A는 추천을 살짝 수정(밥→현미밥)해 저장하고 이력이 학습된다. 주말에 A는 **건강 리포트**에서 4주 체중 추이·주간 영양 균형·"단백질 15% 부족" 요약을 확인하고, 부족분을 채우는 **자동 장보기 리스트**를 우선순위와 함께 받는다.

### 2.2 Acceptance Scenarios

| # | Given (전제) | When (행동) | Then (기대 결과) |
|---|---|---|---|
| **AS-1** | 건강 프로필·알러지를 등록한 사용자 | 보유 식재료를 입력하고 추천 요청 | 알러지 항목이 배제되고 건강 프로필에 맞는 식단이 칼로리·탄단지와 함께 추천됨 |
| **AS-2** | 피드백 이력이 N건 이상 누적된 사용자 | 추천을 요청 | 과거 만족도가 높았던 카테고리/식재료의 가중치가 상향되어 추천 순위에 반영됨 |
| **AS-3** | 유통기한이 임박한 보유 재료 존재 | 식단을 생성 | 임박 재료를 우선 소비하는 식단이 상위에 노출되고 임박 사유가 표시됨 |
| **AS-4** | 보유 재료 중 임박/만료 항목 존재 | 대시보드 진입 | "임박 식재료 N건" 알림과 소비 우선순위 목록이 표시됨 |
| **AS-5** | 추천 결과를 받은 사용자 | 추천을 부분 수정 후 저장 | 수정 이력이 저장되고 이후 추천에 해당 선호가 반영됨 |
| **AS-6** | 과거에 저장한 식단이 있는 사용자 | "다시 추천/재사용" 선택 | 저장 식단 기준 재사용 추천이 생성되고 재사용 횟수가 기록됨 |
| **AS-7** | 체중을 주기적으로 기록한 사용자 | 건강 리포트 진입 | 기간별 체중 추이, 주간 평균 영양 균형, 부족/과잉 영양소 요약이 그래프로 표시됨 |
| **AS-8** | 추천 식단이 일일 권장 영양 대비 부족 | 장보기 리스트 생성 | 부족 영양소를 채우는 식재료가 우선순위·수량과 함께 자동 정리됨 |

### 2.3 Edge Cases

- **EC-1**: 콜드스타트(신규/저활동) 사용자 → 기본 프로필 기반 추천 폴백 + 학습 미적용 명시
- **EC-2**: 상충 피드백 → 최신성·빈도 가중 종합, 신뢰도 임계 이하면 중립 처리
- **EC-3**: 유통기한 미입력 재료 → 임박 추천 제외, 일반 추천 포함, 입력 보완 유도
- **EC-4**: 임박 재료만으로 균형 불가 → 임박 우선 + 부족분 장보기 병행
- **EC-5**: 건강 기록 1~2건뿐 → 추이 그래프 대신 "데이터 누적 안내"
- **EC-6**: 학습 선호가 알레르기/기피와 충돌 → **결정적 안전 검증이 항상 우선**
- **EC-7**: 추천 다양성 고착 → 다양성 보장 로직으로 주기적 변형
- **EC-8**: 외부 상품/헬스케어 API 미연동·실패 → 내부 데이터만으로 정상 동작(graceful degrade)

## 3. Functional Requirements *(필수)*

### 3.0 기반 — 회원·프로필·기본 추천 (단기 MVP, 완료)
- **FR-050 (회원/인증)**: 사용자는 이메일+비밀번호로 가입·로그인하며, 비밀번호는 해시 저장하고 세션은 토큰 기반으로 관리되어야 한다.
- **FR-051 (건강·알러지 프로필)**: 사용자는 키/체중/목표·알러지·기피·질환 정보를 등록·수정할 수 있어야 하며, 민감 항목은 보호되어야 한다.
- **FR-052 (식재료 입력)**: 사용자는 보유 식재료를 입력·관리할 수 있어야 한다.
- **FR-053 (AI 기본 추천)**: 보유 재료 × 개인 영양 프로필 × 1인 가구 조건으로 식단을 추천해야 한다.
- **FR-054 (영양 계산)**: 공공 영양 DB 기반으로 추천 식단의 칼로리·탄단지 등 영양값을 계산·표시해야 한다.
- **FR-055 (결정적 안전 검증)**: 알레르기/기피 식재료는 LLM 외부의 결정적 코드로 차단되어야 한다.
- **FR-056 (면책 고지)**: 추천/리포트에는 "의학적 진단·처방이 아님" 면책이 포함되어야 한다.

### 3.1 AI 추천 고도화 · 피드백 학습 (중기 P1)
- **FR-001 (개인화 가중치 학습)**: 누적 피드백·재사용·수정 이력을 반영해 식재료/카테고리별 선호 가중치를 산출·적용해야 한다. 학습은 **통계 가중치·규칙 기반**(최신성·빈도 가중)이며 별도 ML 파이프라인은 도입하지 않는다.
- **FR-002 (피드백 수집 확장)**: 만족도(척도)·코멘트와 추천 부분 수정(교체·제외·대체) 이력이 수집되어야 한다.
- **FR-003 (학습 반영 가시성)**: 추천 결과에 "왜 이 추천인지" 근거가 표시되어야 한다.
- **FR-004 (콜드스타트 처리)**: 학습 데이터 임계 미만 사용자는 기본 프로필 추천으로 동작하고 학습 미적용이 구분되어야 한다.
- **FR-005 (안전 검증 우선)**: 학습 가중치는 알레르기/기피 결정적 차단을 절대 무력화하지 못한다(FR-055 강화).
- **FR-006 (다양성 보장)**: 동일/유사 식단의 단기 반복 추천을 방지하는 다양성 로직이 적용되어야 한다.
- **FR-007 (추천 정확도 측정)**: 채택률·만족도 기반 정확도 지표가 산출·집계되어야 한다(목표 75% 이상).

### 3.2 식재료 소비 · 유통기한 관리 (중기 P1)
- **FR-010 (유통기한 관리)**: 식재료에 유통기한을 입력·수정할 수 있고, 각 재료는 임박 임계 산정을 위한 **식품군**으로 분류되어야 한다.
- **FR-011 (임박 알림)**: 임박 재료를 감지해 **인앱(대시보드)** 통지해야 하며, 임박 임계는 **식품군별 차등** 적용한다.
- **FR-012 (소비 우선순위 추천)**: 식단 생성 시 임박 재료를 우선 소비하도록 반영하고 임박 사유를 표시해야 한다.
- **FR-013 (소비 패턴 기록)**: 추천 채택/식단 저장에 따른 소비가 기록되어 소비 패턴으로 축적되어야 한다.
- **FR-014 (만료 처리)**: 만료 재료는 추천에서 제외되고 정리 안내가 제공되어야 한다.

### 3.3 식단 저장 · 재사용 (중기 P1)
- **FR-020 (식단 저장)**: 추천 식단을 이름/메모와 함께 저장할 수 있어야 한다.
- **FR-021 (식단 재사용)**: 저장 식단 기반 재추천을 받을 수 있고 재사용 횟수가 학습에 반영되어야 한다.

### 3.4 건강 분석 리포트 · 시각화 (중기 P2)
- **FR-030 (건강 기록)**: 체중·주요 건강 지표를 **수동으로** 기록할 수 있어야 한다(핵심 경로는 수동 입력만으로 완결).
- **FR-031 (추이 시각화)**: 기간별 체중·건강 변화 추이를 그래프로 제공해야 한다.
- **FR-032 (영양 리포트)**: 주/월 평균 영양 균형·부족/과잉 영양소 요약을 시각적으로 제공해야 한다.
- **FR-033 (캘린더 뷰)**: 식단 이력을 캘린더로 조회할 수 있어야 한다.
- **FR-034 (면책 고지)**: 모든 건강 리포트에 "의학적 진단/처방 아님" 면책을 포함해야 한다.

### 3.5 자동 장보기 리스트 고도화 (중기 P2)
- **FR-035 (부족분 자동 정리)**: 추천/저장 식단과 보유 재고를 비교해 부족 식재료를 수량과 함께 자동 정리해야 한다.
- **FR-036 (구매 추천 우선순위)**: 장보기 항목은 영양 부족도·임박 대체 필요성 기준으로 우선순위가 매겨져야 한다.

### 3.6 데이터 · 거버넌스 · 연계
- **FR-037 (데이터 관계 강화)**: 사용자/식단/추천/피드백/소비 데이터가 관계형으로 연결되어 학습·리포트 근거로 사용되어야 한다.
- **FR-038 (민감정보 보호)**: 건강·체중 등 민감 데이터는 앱 레벨 암호화·동의 기반 체계를 준수해야 한다.
- **FR-039 (입력 검증)**: 사용자 입력(식재료·유통기한·체중)은 검증되어 비정상 값이 학습/리포트 품질을 훼손하지 않아야 한다.
- **FR-040 (선택적 외부 연계)**: 공공 영양 데이터·식품 상품 정보·헬스케어 기관 데이터 연동은 **가능한 경우 확장**하되, 미연동 시에도 핵심 기능이 정상 동작해야 한다.

---

## 4. Success Criteria *(필수)*

- **SC-001 (추천 정확도)**: 채택/만족도 기반 추천 정확도 **75% 이상**.
- **SC-002 (추천 만족도)**: 추천 식단 만족도 평균 **80% 이상** 유지.
- **SC-003 (음식물 폐기 절감)**: 임박 우선 소비 사용자의 폐기율 도입 전 대비 **20% 이상 감소**.
- **SC-004 (식단 생성 시간)**: 추천 확정 소요 시간 기존 대비 **50% 단축**.
- **SC-005 (사용자 유지율)**: 4주 유지율 **70% 이상**.
- **SC-006 (학습 체감)**: 사용자 **80% 이상**이 "추천이 취향에 맞게 개선됐다"고 평가.
- **SC-007 (임박 알림 적시성)**: 임박 식재료는 만료 전 알림 제공, 임박 항목 우선 소비 추천 노출률 **90% 이상**.
- **SC-008 (리포트 가용성)**: 충분한 기록이 있는 사용자는 체중 추이·영양 균형 리포트를 즉시 확인 가능.
- **SC-009 (추천 응답 성능)**: 추천 응답 P95 **≤ 30s**.

---

## 5. Key Entities *(데이터 관련)*

- **사용자(User) / 건강 프로필(HealthProfile)**: 회원 정보 + 키/체중/목표·알러지·기피·질환(민감, 암호화). (1:1)
- **식재료 보유 항목(InventoryItem)**: 유통기한/소비기한, **식품군 분류**, 임박 상태, 소비 여부. (사용자 1:N)
- **식품 영양 마스터(Food)**: 공공 영양 DB 기반 100g당 칼로리·탄단지·식이섬유·나트륨.
- **추천 요청·결과(Recommendation)**: 학습 가중치·임박도 반영 근거와 정확도 측정 기준.
- **영양 분석(NutritionAnalysis)**: 추천별 총 영양·RDA 비율.
- **피드백(Feedback) [확장]**: 만족도·코멘트 + 추천 수정 이력(교체/제외/대체).
- **사용자 선호 모델(UserPreferenceWeights)**: 식재료/카테고리 선호 가중치(피드백·재사용·수정에서 파생). (1:1)
- **식품군 임박 임계(FoodGroupExpiryThreshold)**: 식품군별 임박 판정 일수 기준.
- **소비 패턴 기록(ConsumptionRecord)**: 소비 이력. (사용자 1:N)
- **저장 식단(SavedMealPlan)**: 저장 식단·재사용 횟수·메모. (사용자 1:N)
- **건강 기록(HealthLog)**: 시점별 체중·건강 지표(민감, 암호화). (사용자 1:N)
- **건강/영양 리포트(HealthReport)**: 기간별 집계 요약(파생/캐시).

## 6. Assumptions (가정)

- 단기 MVP(001: 회원/프로필/식재료/AI 추천/영양 검증/피드백/장보기)와 중기 고도화(002: 적응형 추천·유통기한·건강 리포트·장보기 고도화)는 **구현·운영 중**이며 본 통합 명세의 기반이다.
- "학습"은 **통계 가중치·규칙 기반** 개인화이다(ML 파이프라인 미도입). *(Clarified 2026-06-05)*
- 알림은 **인앱(대시보드) 통지만** 제공한다. *(Clarified 2026-06-05)*
- 건강/체중 데이터는 **사용자 수동 입력**으로 수집한다. *(Clarified 2026-06-05)*
- 유통기한 "임박" 임계는 **식품군별 차등 기준**(설정값)으로 관리한다. *(Clarified 2026-06-05)*
- 외부 상품/헬스케어 API는 가용성이 보장되지 않으므로 핵심 경로는 내부 데이터만으로 완결한다.
- 추천 응답 성능 목표(P95 ≤ 30s)를 유지한다.

## 7. 위험 · 제약 · 거버넌스 (Risks & Governance)

| 위험 | 영향 | 완화 방안 | 책임 주체 |
|---|---|---|---|
| **AI 추천 오류·영양 불균형** | 사용자 신뢰도 저하 | 결정적 영양/알레르기 검증을 학습보다 우선, 추천 로직 테스트 강화 | AI 개발팀 |
| **입력 데이터 품질 저하** | 학습/리포트 신뢰도 하락 | 입력 검증(FR-039), 이상치 필터, 콜드스타트 폴백(FR-004) | 데이터 관리팀 |
| **AI API·서버 비용 증가** | 운영 부담 | 추천 캐시·재사용 활용, 클라우드 비용 최적화, 기능 우선순위 개발 | 운영 관리자 |
| **초기 사용자 이탈** | 사용자 감소 | 개인화 체감 강화(FR-003), 리포트로 가치 가시화, 리워드 검토 | 서비스 운영팀 |
| **민감 건강정보 유출** | 법적·신뢰 리스크 | 앱 레벨 암호화·동의 기반 수집(FR-038), 최소 수집 | 데이터 관리팀 |

**거버넌스**: AI 개발팀(추천 알고리즘·모델 개선), 데이터 관리팀(데이터 품질·검증), 서비스 운영팀(피드백 분석·개선).
